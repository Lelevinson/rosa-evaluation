# Improved ROSA: M1–M5 recap

Date: **2026-10-30**. Current status: **technical delivery complete locally, with
mixed research findings and explicitly unfulfilled review/backup items**.

**Goal.** Improve ROSA's surrounding software so existing models execute robotic
tasks with less orchestration overhead and reliable outcome reporting. No model
training is involved. The tested backends are local Qwen3.5 9B through Ollama and
hosted Sol through the existing OAuth adapter. These M1–M5 milestones concern the
bounded macro deliverable; they are separate from the older six-stage roadmap.

**What was built.** The model selects a permitted registered skill and classifies
the result. A Python macro handles routine prerequisite reads, at most one
necessary movement and fresh outcome verification. This implements task
decomposition and program-managed routine tool execution. The model still makes
semantic selection/clarification decisions. It is one selected skill per
invocation, not a general multi-step planner or a new tool-selection algorithm.

**M4 results and speed.** Each row contains 20 trials. Costs include unsuccessful
attempts. Passing includes the prescribed grounded FAILURE/UNKNOWN or clarification
where appropriate; it is not simply the number of successful movements.

| Backend / condition | Correct | Model calls | Input tokens | Output tokens | Native operations | Mean task seconds |
|---|---:|---:|---:|---:|---:|---:|
| Sol / primitives | 20/20 | 68 | 95,333 | 2,221 | 38 | 16.42 |
| Sol / macro | 20/20 | 38 | 48,754 | 1,145 | 40 | 9.73 |
| Qwen / primitives | 15/20 | 91 | 207,958 | 19,445 | 50 | 133.49 |
| Qwen / macro | 14/20 | 53 | 105,779 | 12,519 | 48 | 85.18 |

Sol used 44.1% fewer model calls and 40.7% less task-loop time with macros, while
native operations increased 38→40. Qwen used 41.8% fewer calls and 36.2% less task
time across all attempts, accompanying lower correctness. On the 13 paired cases
where both Qwen conditions passed, calls fell 53→28 (47.2%) and task time fell 50.8%.
That selected subset describes successful pairs; it does not erase failures.

Closed M4 backend elapsed time was 17.68 minutes for Sol and 81.97 minutes for Qwen,
including setup, resets, independent checks, trace auditing and cleanup. Mean task
times above exclude those costs. Different hardware, serving and tokenization
prevent interpreting the observed backend gap as an intrinsic model-speed ranking.

**Fairness and observability.** Both execution conditions shared the five public
tools, catalogue, application permissions, report contract, safeguards and budgets.
Per task: 8 model calls, 2,048 observed output tokens, 10 native operations, at most
one movement and 360 seconds. Qwen used 8K context and up to 1,024 output tokens/call.
All 250 requests have usage records; there were no censored/unstarted M4 cells,
infrastructure retries or OAuth/quota interruptions. The 80 live audits matched
3,290 spans; 20 controls added 202 spans. All 62 frozen source digests remain intact.

**What the results support.** The reusable macro reduces LLM orchestration overhead
in this tested environment, with a favorable Sol engineering result. It does not
establish a general reliability improvement, a Qwen reliability gain, a novel
selection algorithm or superiority to untouched upstream ROSA. The comparator
already contained our shared repairs. Native robot work was not uniformly reduced.

All 11 failed Qwen trials selected inspection; only five ended in accepted,
evidence-grounded SUCCESS reports that failed the requested goal. The other six
ended in errors. Verifying a selected skill does not guarantee that it satisfies
the user's intent. In the retrospective partial-command review, primitive paths
recovered after an initially rejected read; macro paths committed to inspection
before attempting a blocked reselection. This describes observed paths, not a
causal proof about prompt wording. One-skill commitment is a documented trade-off.

**Human review and future wording.** Martin submitted eight ratings, passing the
four inspections and failing the four clarification responses. He later clarified
an outcome-oriented preference and requested concise, explicit task wording.
These judgments oppose the frozen ambiguity criterion and are retained as
stakeholder feedback. They are not independent external adjudication applying
that rule; prior aggregate-result exposure is disclosed. No old scores changed.
For future known-goal tasks, state the action and target directly. If essential
intent is missing, ask one short question. Clearer prompts remain a proposed
direction, not a demonstrated Qwen improvement or an implemented prompt rewrite.

**Scope and current decision.** Keep the bounded module optional and report the
backend-specific trade-offs. Evidence covers one six-joint UR5e, movement plus
read-only inspection, ten project-authored task families and two repetitions.
Observers are separate from the agent but share the simulator/ROS interfaces.
No broad generalization, collision/path safety, physical hardware, multi-skill
autonomy, verified episodic memory or full JTVR benefit is established. No new
architecture or research campaign is currently scheduled.
