# F1 cases

| File | Content |
|---|---|
| `heldout.json` | 30 fresh held-out cases, `F1-ho-001` … `F1-ho-030`, each with `case_sha256` (canonical JSON) |
| `dev.json` | Pointers to the 18 frozen G1 dev cases (corrected from 16 on 2026-11-21; see PROTOCOL §12 D10), with per-case SHA-256 and the `stage-1/cases.json` file hash |
| `template-groups.json` | 15 template groups (bootstrap units), 2 cases each (arm and base) |

Generated by `tools/f1_wording/build_cases.py` and `tools/f1_wording/leakage_check.py`. Both are
deterministic and stdlib-only.

**Authorship:** every held-out request was written by Claude (Opus 5.5, AI) for Martin on 2026-11-21. The
reviewer, Levinson, did not write or edit them. They were written and hashed before any F1 run, using only
the frozen G1 world semantics. The domain nouns, coordinates and check names are fixed by `worlds.py`.

**Schema:** G1 case fields (`kind`, `skill_id`, `fault`, `world_configuration`, `expected_status`,
`expected_dispatches`, …), so the frozen G1 scorer applies unchanged. F1 adds `f1_type`, `template_id`
and the authorship fields. A movement-with-prerequisite case with a readable pose uses G1 `kind: write`.
One with the pose unavailable uses `kind: missing_prerequisite` and `fault: missing_pose`.

**Leakage calibration** (same metric and normalization; demonstrated with the checker's own `compare()`):
- the same G1 template in the other domain scores 1.00 / 1.00;
- a close paraphrase of M4 09 scores 0.68 / 0.62 (flagged);
- a loose paraphrase of G1 032 scores 0.70 / 0.20 (flagged);
- two different G1 templates score 0.10 / 0.00.

All 30 F1 cases are below the REVIEW line. The maximum is 0.38 / 0.11. The check is lexical: it cannot
separate a shared *task type* (move only if current position evidence exists) from paraphrase, and that
type is required by design.
