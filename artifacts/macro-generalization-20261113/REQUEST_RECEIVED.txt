Date: 2026-11-13. Scope: a new, separate study. It does not revise M1-M5, the timing probe or Phase 1.
Context (informational, not authorization). M4 showed that bundling cut model requests by about 42-44% on a four-skill, short-horizon, single-arm catalogue. We want to know whether that result generalizes along three axes: bundling depth, a second domain, and catalogue size. The study should be able to come out against us. Nothing beyond Stage 0 starts without the user’s confirmation.

0.1 Domains.
- A: arm (mock). Use the existing isolated stateful mock world, not Gazebo. State which existing mock you reuse and confirm it has a separate observer. Gazebo is out of scope for G1.
- B: mobile base (mock, new). Nodes could include battery, localization validity, path clear and map-lock state, with a goto write and a pose verification. Codex may propose different sources, but B must not be a reskinned arm. Its nodes, units and fault types must differ in kind.
0.2 Catalogue, per domain (6 skills).
- Read-only ladder, four skills. These inspect d = 1, 2, 4, 6 distinct nodes, one separately metered source per node. Native depth = d.
- Write anchors, two skills. Each is a state change with p prerequisite reads, one conditional write and one fresh verification, with p = 1 and p = 3 (native depth 3 and 5).
- Use the same catalogue schema as M4. Do not add plain-language descriptions, which would be a separate intervention. Skill IDs must not hint at depth.
0.3 Per-skill depth table (record before freeze). For each skill record:
- native depth, meaning the number of metered operations on the nominal macro path
- minimum primitive model calls assuming full batching of reads, and maximum assuming one node per call
- whether the reads are independent or dependent
0.4 Cases (held-out about 64, dev about 32).
- Ladder cells: 5 held-out cases per domain-depth cell, which is 40.
- Write anchors: 3 held-out cases per anchor skill, which is 12.
- Non-depth cases: 12 held-out, per domain 2 missing-prerequisite, 2 ambiguous and 2 fault cases (ineffective or partial write, unavailable source).
- Include correct-inspection and correct-movement requests, with paraphrases.
- Split dev and held-out by request template group, never by individual case. Paraphrases of one template stay together. No case reuses an M4 template.
- At least one third of cases are authored by the teammate, blind to all results. Record each case’s author.
- Ambiguous cases are scored under the M4 frozen rubric (clarify) and separately under the alternative “inspection acceptable” view. Neither enters the depth analysis.
0.5 Budgets (common to both arms, frozen).
- Model calls per task: nominal primitive path (maximum calls) + 4. Native operations: nominal depth + 4. Tool attempts: calls × 2. Corrections: 3. At most 1 movement dispatch. Wall time 360 s.
- Keep M4’s Qwen settings unchanged: context 8192, 1024 tokens per call, temperature 0, seed 42, thinking off, and the 2048 observed-output gate.
- Codex proposes final numbers. The user confirms them.
- Endings caused by budget exhaustion are labeled separately from wrong decisions.
0.6 Conditions. Primitives and macro, with the same system prompt and condition sentences as M4. The condition-wording confound carries over, so state it. Do not reword anything.
0.7 Scoring columns (kept separate).
- selection correct (first accepted skill, or a valid clarification)
- execution correct (the right operations, fresh verification, no dispatch violation)
- report correct (the status matches observed state, the observation is task-local)
- primary pass (the full frozen contract)
- budget-exhaustion flag and length-stop flag
- per primitive run: reads per read_state call (batching)
- Evidence truth and goal correctness are scored independently, as in M4.
0.8 Predictions and decision rule. Each outcome is Support, Against or Uninformative. A ceiling is Uninformative, not Support.
Analysis rules:
- Per-depth and per-domain tables, with discordant-pair counts.
- Bootstrap intervals resample case clusters (template groups), with no pooled p-values.
- Report all-attempt and matched-success costs side by side.
- Note that depth is confounded with horizon and context length, and that independent versus dependent reads is a separate factor.
- With about 10 cases per depth, say outright that only large effects are visible.
