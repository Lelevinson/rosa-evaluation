# One prospective scorer-defect amendment cycle

Date: **2026-11-14**. Recorded after the zero-inference authorization preflight,
before any G1 live model results. This consumes the **one permitted case/scorer
revision cycle**. No case, prompt, guard, condition sentence or public module is
changed. Original Stage 1 scorer, frozen files, scores and evidence remain intact.

The Stage 1 scorer uses exact native counts as part of execution correctness.
Those counts are necessary structural-control expectations, but applying them
to live task correctness would reject extra permitted reads even when scope,
freshness, dispatch, reporting and resource bounds hold. The written contract
permits bounded read-only recovery. The live scorer requires the requested path
and authorized source set, permits additional acquisitions of those same sources,
and reports their full cost separately. Scripted expected counts remain descriptive
comparators, never revised live expectations. The native-ratio retention band is
unchanged and can fail even when a task's correctness passes.

An explicit request saying **"no additional acquisitions"** is stricter than the
general recovery allowance: its primary acquisition cap remains the requested
native depth. This applies to dev-002, dev-004, dev-010 and dev-012. Their request
text is unchanged. Other cases still forbid acquiring unlisted sources; permitted
repeat acquisitions are not automatically a correctness failure. This prospective
interpretation is frozen before live outcomes and disclosed as a wording constraint.

The old scorer also derives required report fields from the requested case depth
when evaluating a different selected inspection skill. This can incorrectly label
a truthful, accepted report for the wrong skill as false evidence. The live scorer
validates report evidence/classification against the selected public definition,
then evaluates requested-goal selection and scope separately. A truthful wrong-
skill report still fails primary requested-goal correctness.

Null evidence must match an actual recorded failed acquisition and the cited
observation's unavailable provenance; case labels alone do not establish this.
Budget/length flags are set from actual gate outcomes. Accepted unsupported SUCCESS,
rejected SUCCESS attempts and grounded SUCCESS for a wrong goal are separate fields.
Clarification retains the frozen primary question screen and review flag; its
inspection-acceptable sensitivity view is separate and not primary.

Validate before launch: rescore all 132 retained Stage 1 snapshots with no primary
score changes; reject actor-only truth, stale references and invented values;
test that extra authorized reads preserve correctness while increasing cost, and
that truthful wrong-skill evidence stays factual but fails requested-goal scoring.
Save tests and validation separately under Stage 2. These are engineering checks,
not new model data or a revision to Stage 1's published results.

No later case/scorer revision cycle is available in this dev stage. If another
defect blocks valid interpretation, stop and report it with retained data rather
than silently repairing/replacing outcomes.
