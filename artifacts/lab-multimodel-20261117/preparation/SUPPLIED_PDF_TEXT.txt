What we proposed
 Names not final
Goal: small local models give more correct, source-backed answers with ROSA's robot tools, at
no extra cost.
Problem: small models make small slips, and original ROSA ends the whole run on a slip.
Main: steady loop
Four small fixes around ROSA's
agent loop, so a slip does not end
the run.
Add-on: list sweep
After two reads from a list, the
system reads the rest of it.
Add-on: name fix
The system corrects short names in
the final answer.
Tried and dropped: answer check, list arguments. We do not claim these ideas are new; we compare with related work later.

Add-on 1: List sweep
 Tested: works when it fires; rare
List nodes
 Read /a
 Read /b
 System reads /c, /d,
/e
 Model answers
After two same-kind reads from one list, the system reads the rest (up to 20 names) and attaches the results.
When it fires (practice tasks)
Model re-asked: 15% (vs 65% without)
1.6 fewer requests per firing
14% fewer tokens after firing
No wrong answers caused
Limits
Rare: 17–20 firings, mostly 2 tasks
Smallest model: no gain
Whole-run totals unchanged
Final exam: room on only 2 of 48 tasks. A small side
finding, not a main claim.
Why it matters: a list option the model had to use itself was used in 4 of 80 runs. When the system acts, the model uses
the result.

Add-on 2: Name fix
 Tested in recording mode only
Model answers "zircon"
 One seen name ends with it:
/e1h/basalt/zircon
 Answer says /e1h/basalt/zircon
The system keeps the full names seen in tool results. At the final answer, a short name that matches exactly one full name is replaced.
Safe by design
Two matches, or a name never seen: left alone.
Never invents a name.
Round 2 (recorded, not applied)
0 of 296 answers harmed
2 fixed (same task)
Small: the final exam has room for it on about half the tasks. Not yet tested live.
