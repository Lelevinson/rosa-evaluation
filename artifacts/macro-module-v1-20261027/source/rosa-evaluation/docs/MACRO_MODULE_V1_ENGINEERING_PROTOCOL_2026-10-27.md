# M1 engineering validation, separate from historical research campaigns

User authorized M1 on 2026-10-27 and separately chose optional protected OAuth
persistence across restarts with explicit sign-out. No live-model benchmark,
new hardware, second capability or teammate-backend migration is included.

This is iterative engineering acceptance, not a prospectively frozen model
performance study. Development failures are retained under distinct attempt
directories. No old protocol/source/score is edited to accommodate a repair.

Validation:

1. Inspect branches/dirty work, exact installed dependencies, prior stopped
   campaign and simulator processes. Record credential-free environment data.
2. Run targeted public API/agent tests and existing research/evaluation
   regressions. Both actual adapter classes use fake transports, never providers.
3. Run twelve scripted real-ROSA cases: six known fixture paths in primitive and
   macro configurations. Require original local auditing plus exact persisted
   Phoenix spans and closed trees. These are scripted correctness checks only.
4. Run seven deterministic UR5e checks via the installed public module: already
   home, move offset, already offset, ineffective home, unavailable prerequisite,
   return home, partial offset. Use a separate read-only observer; preserve
   controller records, actor evidence, explicit outside-task HOME reset and
   cleanup. External 300-second process alarm includes setup/checks; all native
   I/O retains existing bounded waits. Each invocation still allows one write.
5. Build a wheel offline from copied source, install into an empty temporary
   target and assert that imported ROSA/macro files come from that target.
   Reuse pinned dependencies explicitly; this is not a fresh-OS installation.
6. Validate optional OAuth persistence with synthetic protocol tests, Windows
   DPAPI round trip, exclusive profile lease and deletion of the synthetic
   record. No real credentials or provider sign-in are used.
7. Verify all previous frozen hashes read-only; capture M1 sources/locks, logs,
   revisions and outcome limitations in a checksummed evidence package.

Do not add results to the 69/72 macro-focus study. Do not claim new Qwen/Sol
performance, verified gripper capability, general task planning or physical
robot safety. Report PASS/FAIL/NOT YET TESTED and stop at the M1/M2 boundary.
