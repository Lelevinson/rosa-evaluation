# Simplified Stage 4 completion

The frozen [protocol](../../docs/STAGE4_BATCHING_COMPLETION_PROTOCOL.md) separates
reliability interventions from real-ROS batching. Artifacts live in
`artifacts/stage4-batching-completion-20261021/`. This is separate from the
preserved movement V2 preflight and original-JTVR policy comparison.

Both arms use actual ROSA and the same helper/native tools. Reference honors
model-selected direct/bulk/node_bulk plans; candidate applies amortized selection
to model-generated, validated requirements. No missing requirement is silently
filled. Shared continuation capabilities prevent an artificial inference-saving
advantage. Native reads are individually recorded and actor-tagged in Phoenix.

There are 48 reliability and 32 batching trials per backend, maximum 1,056 model
requests/backend. The supervisor runs hosted, hosted audit, local, local audit;
consent is fresh and tokens are memory-only. It refuses to overwrite a launched
campaign. Run the audit in the separate Phoenix environment; the live runner
uses the research uv environment. Reconstruction requires the exact frozen
evaluation AND sibling research sources, not just their base Git commits.

The source snapshots, all preflight failures, resets, evaluator queries, real
server callback values and model trial failures are retained. The final report
and package modules are post-run analyses and are separately snapshotted.
Do not rerun into existing campaign directories or modify a frozen protocol.

`BoundedGateway` is a separately tested hardening class for future campaigns: it
extends the read manager's 24-operation guard to write dispatches. The frozen
live experiment imports the original `Gateway`; it has not been changed or
silently switched to this class. Report observed operation counts and this
limitation alongside the separately tested fix.
